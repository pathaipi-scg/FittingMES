# FittingMES Response Format

## Purpose

This skill controls RESPONSE FORMATTING ONLY.

It does not define LOGGER logic, SQL design, database rules,
implementation rules, file locations, or business semantics.

## Required response format

Return the entire final response as one Markdown blockquote.

Every visible line must begin with exactly:

This applies to everything in the response, including:

-   headings
-   normal paragraphs
-   bullet lists
-   numbered lists
-   SQL
-   CREATE TABLE statements
-   ALTER TABLE statements
-   SELECT statements
-   Python
-   PowerShell
-   JavaScript
-   HTML
-   JSON
-   configuration examples
-   file paths
-   schemas
-   examples
-   warnings
-   conclusions

There must be no visible final-response line outside the Markdown
blockquote.

## Never create code blocks

Do not use fenced code blocks.

Do not use triple backticks.

Do not use indented code blocks.

Do not indent SQL or other technical examples by four spaces.

Do not use Markdown inline-code formatting with backticks.

Do not use syntax-highlighted blocks.

Do not create a separate code/code-copy box.

SQL and all other technical content must be ordinary Markdown blockquote
text.

## SQL example

Wrong:

CREATE TABLE dbo.LoggerEvent ( LoggerEventID bigint )

Correct:

> CREATE TABLE dbo.LoggerEvent ( LoggerEventID bigint, ProductionDate
> date NOT NULL )

Every SQL line must start directly with \>.

Do not add four spaces after \> because Markdown may render the content
as a code block.

## Other technical content

The same formatting rule applies to:

-   Python
-   PowerShell
-   JSON
-   HTML
-   JavaScript
-   configuration
-   environment variables
-   file paths
-   command examples

All must remain ordinary blockquote text.

## Do not defeat the format rule

Do not use:

-   HTML pre or code tags
-   escaped indentation
-   encoded spaces
-   HTML entities intended to create indentation
-   any other formatting technique that creates a code/code-copy box

Prefer simple plain text after \>.

## Tool UI

Tool-execution UI generated by Copilot or Agent, such as Ran, Search,
Read, command approval cards, terminal previews, and confirmation
prompts, is separate from the final written response.

This skill controls the final written response only.

## Final self-check

Immediately before sending any final response, verify:

1.  Every visible line begins with \>.
2.  No triple backticks exist.
3.  No fenced code block exists.
4.  No indented code block exists.
5.  No inline backticks exist.
6.  SQL is plain blockquote text.
7.  Technical examples are plain blockquote text.
8.  There is no separate code/code-copy box.

If any check fails, correct the response before sending it.

## Scope boundary

This file is only a response-format skill.

Do not use this file as a source of truth for:

-   LOGGER design
-   SQL schema
-   Master data semantics
-   Cause behavior
-   database relationships
-   implementation approval
-   repository behavior
-   application logic
-   business rules

Those subjects belong in their own design/context documents.
